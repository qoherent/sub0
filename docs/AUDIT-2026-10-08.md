# Subzero audit — 2026-10-08

Status: the bounded audit and local hardening are complete. Twenty-one confirmed finding groups were corrected with retained regression evidence. The final production code passed build/typecheck and 128/128 tests on Node 26.3.1 and on a fresh Node 24.21.0 setup. Installed default/development consumers and Pi host workflows have evidence below. Public release remains on hold for the explicit qualification, resource-bound and publication gaps; this is not a universal host/provider/OS safety certification.

## Verdict and method

The MCP sidecar, dependency-free core and thin Pi adapter are a coherent implementation of portable delegation. The public transport is not a universal plugin package format. The working baseline hid several failures at credential, cancellation, recovery and packaging boundaries. Passing the original suite was not evidence that those boundaries held.

The audit read all 20 repository Markdown documents, including the owner-owned `vision.md`, current design/usage/testing records and archived research. It examined all current production modules, schemas, manifests, lockfile, configuration loaders, tests and the Pi/SQLite qualification sources. Historical Docker experiments were treated as dated records, not rerun or promoted to current compatibility evidence. `vision.md` was not edited.

The baseline was clean commit `0c3258d3…` on `main`. Changes are local and uncommitted on `audit/hardening-2026-10-08`. No package was published and no branch was pushed. No `.env` values were printed, copied into the fresh snapshot, or read into the audit conversation. The opt-in command loaded the ignored file through Node.

Evidence labels used below:

- **Verified:** an executed test, retained artifact or inspected primary source supports the statement.
- **Inference:** the implementation suggests a consequence, but the specific workload has not been executed.
- **Unknown:** evidence needed for a compatibility or safety claim is missing.

Severity: P1 is a credential/control/recovery failure with consequential effects; P2 is a functional, compatibility or resource-bound failure; P3 is a lower-impact usability or publication gap. Severity describes the pre-fix condition, not an assertion that an actual user key was exposed.

GPT‑6 Luna High (`gpt-6-luna-high`) was used for read-only scouting through Devin CLI after account availability was verified. It produced eight candidate findings but its output ended mid-finding and no exit receipt was retained. It is not counted as a completed independent audit. Findings were checked against code and tests; the pagination and non-Linux-startup conclusions were rejected rather than accepted on model agreement.

Two Hermes Agent v0.21.5 web-only one-shot subagents (`--ignore-rules -t web`, sessions `20261008_140643_9f2aae` and `20261008_140643_754aec`) performed secondary primary-source navigation after the report was drafted. Their outputs are treated as hypotheses; consequential claims were independently verified in the installed dependencies before use below. Context7 was unavailable inside Hermes, so its syntax claims are disclosed as unqueried rather than assumed.

## Vision and design decisions

| Owner requirement | Verified implementation / disposition | Remaining condition |
|---|---|---|
| 1, 6: agnostic/additive delegation | Shared MCP stdio service and language-neutral wire schemas; Pi adapters use that service rather than replacing the parent conversation. Legacy/current MCP exchanges and two Pi host versions were exercised. | No universal plugin manager; Codex/Claude/OpenCode host workflows are still unqualified. |
| 2: child sees the codebase | Canonical host-selected cwd plus explicit researcher/coder read tools; real fixture files were read, searched, listed and edited. | Cwd is context, not confinement; shared checkout and host permissions remain. |
| 3: stop/resume agent sessions | Durable child/run identities, completed-leaf branching, restart discovery, explicit stop confirmation and retained interrupted branches have regression/workflow evidence. | No filesystem rollback; uncertain ownership fails closed and may need operator intervention. |
| 4, 10: bare-minimal engine/no automatic child delegation | Small worker interface; ambient resources/delegation tools are not loaded by built-ins. Retries, recovery compaction and cache warming are disabled. | Full Pi SDK/provider dependencies are not a minimal installed footprint. Arbitrary shell/MCP grants are not a semantic nesting sandbox. |
| 5: templates with own tools/skills/MCPs | Two built-ins, explicit custom definitions, immutable resolved snapshots, named grants and fail-before-model initialization checks. | MCP launch descriptors/tool names are snapshots, not immutable server binaries or a general revocation policy; the child bridge is stdio-only. |
| 7: Pi first/publish at gallery | Thin extension, package entrypoint, license/engine metadata and gallery keyword prepared; local package and host workflows verified. | `private: true` and no publication remain deliberate release blockers. |
| 8: call-selected endpoint/model/key | URL/model/API are call inputs; core receives an in-memory key, while MCP uses an explicitly configured credential alias rather than exposing a literal key to the model. | This is a documented security adaptation of literal-key arguments, not proof that every endpoint/API has compatible metadata. |
| 9: harness-agnostic core | Core imports no Node/Pi/MCP/SQLite module and has no package dependencies; Node/worker/transport details live in runtime/Pi packages. | JavaScript core portability and JSON-schema conformance do not establish every non-JavaScript implementation or host. |
| 11: fx dependency, not fork | No fx fork or dependency exists. The design record rejects fx/libfx for the selected v0.1 seam and chooses Pi SDK 1.0.4 instead. | If fx itself remains a literal owner constraint, this implementation does not meet it; `vision.md` was not rewritten to conceal the difference. |

The local sidecar avoids a listening HTTP/authentication surface and keeps parent/child conversations separate. SQLite transactions and ownership generations are appropriate for cooperative admission; they cannot fence arbitrary OS processes. The observed bugs came from treating cancellation, resolved promises, configuration labels and a build checkout as stronger guarantees than their implementations provided.

## Residual risks, hypotheses and release blockers

These are not silently counted as fixed. They need the stated test or an owner decision.

| ID | Severity / confidence | Evidence and affected assumption | Reproduction or falsification | Remedy / safe boundary |
|---|---|---|---|---|
| R01 | P2, source-verified unbounded shape; operational incidence unknown | `listChildren` selects every retained child, `list` materializes all rows and the schema has no page bound. Idle child count/queues and artifact/transcript retention are not bounded by the four-worker limit. | Seed many idle children/queued prompts and measure response/disk growth. | Add explicit pagination/queue/storage budgets and a retention policy; do not silently truncate JSON or delete user data. |

Persisted template snapshots intentionally survive resume/config changes; template removal is not a demonstrated general revocation mechanism.

## Rejected or limited findings

- **MCP pagination failure — falsified.** The installed client aggregates `listTools()` pages when no cursor is supplied. The two-page grant/execution test passed before any discovery change; no workaround was added.
- **Non-Linux startup necessarily fails — falsified by source.** The receipt writer throws for `null` process identity; non-Linux returns `undefined`, which is accepted. Abrupt recovery remains unknown/fail-closed, not startup failure.
- **Every rejected resume-with-message silently loses accepted work — not established.** A failing RPC does not promise message admission. The reproduced defect was stale dispatch across a generation change, which was fixed without automatic retry.
- **The old live failure was definitely an HTTP-401 bug — unknown.** Its cleanup removed discriminating evidence. The newly reproduced false completion is not retroactively declared the historical cause.
- **No vulnerabilities exist — not established.** npm returned no known advisories in the checked graph; that says nothing about undisclosed flaws or every malicious/configuration workload.
